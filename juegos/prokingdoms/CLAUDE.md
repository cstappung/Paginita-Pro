# Pro Kingdoms

Isometric pixel-art kingdom builder, plain JS with no dependencies, all art generated by code. Written by the
owner outside this repo and dropped in.

**Docs in this folder:**

- `CONTEXTO.md` (how it is built, the platform bridge, the server protocol) and `FIREBASE.md` (cost study): the
  author's notes. Read them before touching the game itself.
- `PLAN-MEGA-ACTUALIZACION.md`: the big plan, phases 0–9, all done (`pk-11` to `pk-40`). Its §1 rules apply to
  every delivery.
- `PLAN-LOGISTICA.md` (Nov 15 2026): the next plan, «Caminos y Campamentos», phases L1–L6 («implementa la Fase
  L<N> del plan de logística»; L6 is the sea with cargo barges). §10 lists traps; §11 has the owner's answered
  decisions (migrate without a reset, carts always on a hand-picked route with no auto mode).
- `NOTAS-ENTREGAS.md`: the full notes of every delivery, with measurements and reasons. Not loaded
  automatically; read the section of the system you touch when a rule below is not enough.

This file keeps only the rules and traps. New notes go here, in a few lines, under their topic.

## How it lives inside Juegos

- **A `tipo: "sitio"` entry** in `SOLOS` (`colabtex/src/juegos/salon-datos.js`), route `#prokingdoms`, full window
  (`html.jg-prokingdoms` in `juegos.html`). The postman is `colabtex/src/juegos/prokingdoms.js` (`crearProKingdoms`);
  the frame sends it `listo`, `volver`, `reportes` and `token` (the Firebase ID token for the server).
- **Open to every account since 2026-11-11** (`SOLO_BETA` false in `functions/index.js`). The beta-tester role
  (`betaTesters/<uid>`, `state.beta`) stays for future games. Guests need an account (`CON_CUENTA_SOLO`).
- **The frame** loads `i18n.js`, `mando.js`, `volumen.js`, then `sitio.js` (defines `window.ProKingdomsPlatform`
  before `js/social.js` reads it, and prepends «← Juegos», volume and «🐞 Reportes» to `#topbar`), then the game.
- **Reports** (`pk-39`): `feedback/<id>` entries with `app: "prokingdoms"` (no node of its own: it would need rules
  published by hand). The page draws the window (`abreReportes`); admin buttons are only hidden, the rules refuse.
  Pure part in `pk-reportes.js`, tested in `colabtex/tests/pk-reportes.test.cjs`.
- **Local mode unless `servidor.json` has a `url`.** Then the postman opens `?api=<url>`; otherwise `?local`.
  Local saves are one kingdom per account per browser (`?perfil` suffix on keys).
- **Kingdom coins are not Juegos coins** and must never reach `monedas.js`. The only link is the Pase del Reino,
  bought with page coins, one way (below).

## Every delivery

- **Cache:** bump `?v=pk-N` on every script and the CSS in `index.html`, bump `PK_VER` in
  `colabtex/src/juegos/prokingdoms.js`, run `cd colabtex && npm run build`. `stamp-version.js` only rewrites the
  `i18n.js` tag here. New `js/` files get the tag too and go into `index.html` in load order (no bundler).
- **Tests:** `npm run test:juegos` (`colabtex/tests/prokingdoms.test.cjs`). After touching `server/sim.js`:
  `node tools/cheat-test.js`, plus the in-process tests of that area (`tools/saqueo-test.js`, `diplo-test.js`,
  `mundo-test.js`, `regata-test.js`). Before a big merge: the Playwright pass over every window at 390×844,
  915×412 and 1280×800, and a `?timelapse` run with an invariant watcher (no NaN, no negatives).
- **Balance changes:** run the autopilot before and after (`?dev&piloto[=N]` or `?timelapse`, `pkPiloto.resumen()`).
  Pace target (`pk-34`): Era II ~10 min, IV ~2 h, V 4–6 h. The pilot must learn any new mechanic first, and its
  `paso()` swallows exceptions (`console.error('piloto', …)`).
- **The Cloud Function is deployed by hand** (`firebase deploy --only functions`); Pages publishes on merge. Bump
  **`D.PROTO`** whenever both sides must agree (map, routes, limits, new building or unit types: `cleanBuildings`
  drops unknown types). Another PROTO gets 426 and the loading screen offers «Jugar sin conexión».
- **World resets:** bump `D.MUNDO_VER` (server wipes all but the suspicion log) and `D.SAVE_V` (saves), update
  `D.NOVEDADES`. A map change needs `D.MAPV` and the POI fixture regenerated (`tests/fixtures/prokingdoms-pois.json`,
  snippet at the top of the test). POI ids are their index in `W.pois`: without a reset, new POIs go at the end with
  their own rng.

## The online server (`functions/`, Cloud Function `prokingdoms`)

- **Same `server/sim.js`** as `node server.js`: `functions/prepara.js` copies it and `js/{util,data,world}.js` (plus
  `pase.js`) into `functions/juego/` and installs `store-rtdb.js` as `store.js`. **Anything the server computes must
  live in those files** (that is why regata, duel, storm and caravan formulas are in `data.js`).
- One instance (`maxInstances: 1`), the world lives in memory; `PK_TICK_PEREZOSO` ticks before a request when 5 s
  passed. Docs are stored as JSON strings in `prokingdoms/col/<col>/<id>` (RTDB drops nulls and empty arrays).
  `flush()` uploads only changed docs.
- `POST /api/join` needs the Firebase ID token; every other route the game token (`X-PK-Token`, or `?t=` for
  `sendBeacon`). CORS only allows the site's origins. New routes go in **both** `server/index.js` and
  `functions/index.js`.
- Sync every 15 s, cloud save every 120 s. Steady sync is small: `diplo` only when its version changes, buildings only
  when `bver` changes. Keep any new shared data versioned the same way.
- Emulator tests: `cd functions && npm run prueba` against `firebase emulators:start --only
  auth,database,functions`; not idempotent (restart between runs). In a cloud session start the emulators with
  `HTTP(S)_PROXY` unset.

## Rules that cross systems

- **Every new bonus must fit the server's anti-cheat in the same delivery**: `LIM.slack` (2.5), `LIM.vida` (1.6,
  mirrored by `D.VIDA_TOPE`), `kindRate`, `armyMultMax`, `defMax`. Gathering bonuses go through `Vida.recoleccion`
  (clamped), never `G.perk('gatherP')`. Never add a gathering bonus to the Pase.
- **PvE only:** heroes, items, encounter `fuerza`, era cards `pve_*`, legends against dragons go in `Exp.powerVs`,
  never in `Social.power` (defense, conquest, the server snapshot).
- **Offline must equal live** (`G.simulateOffline`): use `G.ahora()` (simulated clock), never `Date.now()`, in
  anything the offline calculation runs. Live-only systems (wolves, bandit raids, sieges, live battles) do not exist
  offline, in `?timelapse` or on the server. Choices without the player take a seeded default.
- **Seed per run, not per moment** (`U.rng(r.id, n)`): reloading must never reroll a card, a hand, a room or a drop.
- **One storage-cap rule:** the cap only limits what villagers gather and workshops make. Rewards, chests, loot,
  market buys, sells and trades enter whole (`G.give`, never `G.addRes`). Cargo is never lost: a cart that cannot
  deliver brings it back.
- **New building types live in `data.js`**, not `datos-vida.js` (the server does not load that one). New `Vida.bono`
  keys need a reader (the test fails on unused keys).
- **Toasts** are prepended; hide extras with `:nth-child(n+K)`, never `:nth-last-child`. Same text ignoring numbers
  groups as «×N». At most 3 on desktop, 2 on phones.
- **Phones:** windows are full screen, the portrait panel is `--ph`, bottom-anchored things use `--sab`. Test every new
  window at 390×844 and landscape.
- **Small JS traps:** `U.dayKey` is not zero-padded (parse with `parseDay`); `Element.append(null)` writes «null»;
  do not pass `open` in `U.el` props (read as an event); «~79» reads «-79» in Pixelify Sans, write «aprox.»; digits
  use the Jersey 10 face (`"PK Num"`).
- **i18n:** names people write carry `translate="no"`; never compare against a UI string.

## Economy and workshops

- `S.res` is one number per resource; caps are the sum of TC, Granero and Almacén (`computeCaps`).
  `PLAN-LOGISTICA.md` L3 changes this (stock per building with `S.res` as the town total).
- **Full storage makes gatherers wait** (`G.isFull`, `u.fullWait`) instead of stripping nodes.
- **The workshop reserve** (`G.reservaDe`): a held workshop does not produce at all («En reserva»). Carts recheck
  `reserveOf` **at pickup**, offline belts respect it, and «Producir igual» is always toggled through
  `G.setSinReserva(b, v)` (sends the buffer back). A workshop with no supply (`L.supplied`) takes no workers.
- **The upgrade queue is the player's:** the Maestro mayor and «Mejoras en serie» (`A.SERIE_TIPOS` whitelist) start
  upgrades directly (`A.mejorarYa`), never enqueue, and never spend what the first queued item lacks
  (`G.colaNecesita`).
- **«Meta de era»** steers villagers and workshops (`G.metaNecesita`, `G.metaPide`).
- **Market:** sell ≤ buy − 0.10 at every level (tested); online, `Soc.mercadoLibre` mirrors the server's daily cap and
  `net.js` splits queued ops under `marketSync`. Gold has no `MARKET_BASE` entry (priced at 100 via `price()`).
- **Surplus sinks** priced off caps, not tables: Horas extra (`G.overtime`) and Fiesta (`G.fiesta`).
- `D.NODES` is also read by the server for common zones: changing amounts or regen needs a function deploy.

## Villagers, buildings and the map

- **Buildings build themselves** (`G.updateBuildings`); placing is from Construir (key C). Two taps on touch.
- **Jobs** (`A.JOBS`, `setJob`): a player order sets `task.m` and the Capataz never undoes it; `u.hold` is idle on
  purpose. Capataz moves only its own villagers (`A.rebalance`). Its timers count seconds (`el`), not calls.
- **`u.scared` goes negative after a fright:** test `u.scared > 0`, never `!u.scared`.
- **No building may close the TC's yard** (`G.encierra`, `'encierra'` in `placeWhy`); `G.checkEncierro` handles a
  yard that ends up closed. **Trapped villagers** are rescued by `unstick`: never by distance or path failures alone
  (a villager in its home region is waiting, not trapped). The TC cannot move (`G.MOVE_NO`).
- **Moving buildings** (`G.moveBuilding`, key V) keeps level, timers, queue and buffers; `placeWhy(type, x, y,
  ignorar)` treats its own tiles as free.
- **Camps may go in no-man's land** (`G.OUTPOST`: lumber, mining, mill); everything else only in your parcels.
- **Despeje** (`js/despeje.js`): inside your land only trees and berry bushes stay (`Dz.QUEDAN`); everything else
  moves to the nearest no-man's tile, saved per save. Talar/plantar/quitar are `PK.Def.tool` values. (L4 of the
  logistics plan makes it a pure, global function.)
- **Exploration is an area, not a radius** (`G.exploreArea`, `G.exploreRange` = radius giving that area from your
  home). Every scout reveal goes through `G.revealScout`, never `revealAt`. `W.fog[i]` truthy means explored.
- **Walls** (`js/defense.js`): `W.wall` 1 wall, 2 gate; all tiers upgrade together. Gates let your people through,
  never wolves or enemies (`findPath(..., noGate)`).
- **Map sounds have a place:** use `R.sonarEn` / `sonarEnCasilla`, not `Sfx.play`, for anything happening on the map.

## Combat, expeditions and heroes

- **Live battles** (`js/batalla.js`) run in `G.update` whether watched or not; offline/missions/reloads use the ratio
  formula (`B.adelantar` plays one to the end). **No balance number in `vista`** (effects only). Each figure's hp and
  damage come from `Exp.powerVs` so the planner's «fuerza contra» is what fights; measure changes with
  `B.adelantar` over many fights (bandits ~50% at 1:1, ~100% at 1.3:1).
- Common enemies capped at `TOPE_EN` (1.6); bosses keep their measured numbers (keep a boss's `hp × dps` near a normal
  enemy of its kind). Roles' extras come off every enemy's life. Projectiles whose target fell retarget.
- **Incursions** (`js/incursion.js`): dungeon visits are 5-floor blocks riding on the expedition; each room pays
  `BOTIN_SALA` (35%). The planner's preview of a block is its boss room.
- **Heroes** (`js/heroes.js`): bonus capped at +60% (`H.TOPE_FUERZA`); live troops get 60% of it (`HERO_TROPAS`), the
  ability the rest. Never dead (injured). Daily candidates seeded by day + `created` only. Hero/item ids are per world.
- **Encounters** (`js/aventura.js`) only with a hero; every card has exactly one `cauta` option (the default).
- **Troops are drawn, not simulated** (`js/troops.js`); nothing of them is saved or sent.
- **Raids** (`js/incursiones.js`) from Era II, live only; bandits keep their own spot per tile (`b.dx/b.dy`) and key
  off `b.llego`. Sieges every third raid from Era III. Server raid parties (`tickSaqueos`) from Era IV.
- **Diplomacy, caravans, guild boss, visits, rankings, regata, duels: the server decides** (`sim.js`). Personalities
  use their own rng (`D.SEED + 4243`), never `wrng` (it would move the map).

## Life, events and the Pase

- **Everything Phase 3 gives goes through `G.bono(k)` = `PK.Vida.bono`** (tree, cards, seasons, mood, decorations,
  wonders, Pase gold track), cached and invalidated on picks and season changes.
- Seasons, tide, storms and night follow the real clock (same live, offline and on the server).
- **Events** (`life.js`): `opciones`, `defecto`, `cond`, `tick`; timed effects through `L.ponerMod` / `L.mod`.
- **The Pase del Reino** (`pk-20`): the page buys (`pkPase/<uid>/<period>`, write-once rule), the server decides the
  points (caps per source and per day, jumps clipped). Period arithmetic lives in three places that must agree
  (`pase-pk.js`, the rule, `js/pase.js`; tested in `tests/monedas.test.cjs`). Offline and local: «Requiere conexión».
- **Aspects** are visual and client-only. Colour and frame share one slot with the shop: always reapply with
  `Vida.aplicarAspectos()`. Pass `b.asp` wherever a placed building is drawn.
- Mission ladders (`escalera`): at most 4 visible ranks, **quest ids never change** (hidden steps are `absorbe`d).

## The sea (Archipiélago de Bruma)

- **One live world at a time:** the other waits in `S.otro`; travel serializes, swaps, saves, uploads and **reloads
  the page**. Never swap worlds in place. `main.js` picks local vs cloud save by `S.at`.
- `D.aplicarTema('mar')` mutates the tables once at startup (names, buildings, eras, army, quests); never un-apply.
  Tests that need it load a separate context.
- **Villagers never cross water:** drop points, targets, shops and the rebalancer filter by island.
- The server never sees the sea map; a sea sync carries no snapshot, harvest, market or pase stats.

## Interface, sound and performance

- `js/ui.js` is split: new windows get their own file in `js/ui/` and add functions to `PK.UI`. The core calls
  `UI.barracksQuick`, `UI.enemyText` and `UI.bestVs`: keep them on `UI`.
- **Redraws keep scroll** (`UI.rerender`, `refreshPanel`); pass `rerender(true)` when switching tabs.
- Grouped menu (`GRUPOS`, `agrupar`); buttons keep their `MENU_VER` rule. `.job-row` has 6 grid columns.
- **Sound:** every sound is a recording in `sfx/` with a measured gain (`GAN`); the synthesized `switch` is the
  fallback, do not delete it. Music and ambience go through `sfx.js`' master (M and the shared volume reach them).
- **Performance** (`pk-32`, 300 villagers): the villager sprite cache is an LRU `Map` with a per-frame budget; `mine()`
  in `game.js` is cached (never mutate what it returns); one `fillStyle` per figure; while a battle is open the map is
  not drawn. Measure with `node tools/rendimiento.js`.

## Logistics plan (`PLAN-LOGISTICA.md`)

### L1, routes by time and carts with origin and destination (`pk-41`)

- **`W.rutaCosto(sx, sy, goal, costo, minCosto, maxIter)`** is the A* by time: each tile costs `1 / speed` for that
  traveller (`Infinity` = blocked) and the heuristic uses the fastest tile, so it never overestimates. Villagers,
  wolves, bandits and troops keep `W.findPath` (cost 1).
- **Cost tables per profile** (`L.tabla(perfil)`, `L.PERFIL_DE[kind]`) are rebuilt only when `W.roadVer`,
  `G.blockVer`, `W.terrVer`, `W.apVer` or the road bonus change. **`L.factor(perfil, k)` is the one speed rule**:
  `step()` uses it too (`L.factorUnidad`), so a route's estimated time is the real one.
- **Paths are cached per route** (`L.camino(a, b, perfil)`), at most 2 recomputed per game step (`presupuesto`); a
  stale one is used until its turn. The offline calculation forces them.
- **`step()` only shortcuts a cart through tiles of the same speed** (`parejo` in `entities.js`). Without it a cart cut
  the corner of an L-shaped road through the grass.
- **Routes** (`st.logi.rutas = [{ id, de, a, res }]`, `u.ruta`): load at origin, wait there when there is nothing to
  carry («Esperando carga», leaves with half a load or after 60 s), wait at a full destination with the cargo. **No
  automatic mode** (owner's decision 2): `findJob` is gone. Carts never leave your territory and never serve camps
  (`L.parMalo`); store ↔ store routes are refused while stock is one town pool.
- `put` into a workshop stops at `bufCap`; cargo that no longer fits a changed route goes back (`dropCargo`).
- `L.supplied(b)`: near a store, a belt, or a route ending at it **with carts**. The Capataz's «coming» check only
  counts a cart that is carrying to it.
- **Old saves** (no `st.logi.rutas`): carts lose their job, cargo returns, they stay parked, and `st.logi.avisoRutas`
  shows `UI.avisoRutas` once (after whatever modal is open). The Logística button has a badge with the carts without
  a route, and the Asesor a rule.
- The Carretería makes `2 + 2 × level` carts.


### L2, villagers with a work building and a radius (`pk-42`)

- **Every gatherer of yours works for one building (`task.base`)**: Centro Urbano, a camp, a Mill, a colony dock
  (`G.BASES`: radius and slots per level). It only gathers inside that radius (`G.nodoEnRadio`, measured from the
  building's centre) and drops there. Nothing in the radius → it waits by the building with `task.node = -1`; one
  the Capataz placed (`A.sinRadio`) counts as idle after 20 s and gets another job, **one you sent (`task.m`) waits**.
- **`G.enBase` is cached per game step; every `G.assign` (and any direct write of `task.base`) must call
  `G.baseSucia()`.** Without it the Capataz filled 12 villagers into a 6-slot camp in one step.
- `b.extrae` (saved): what a multi-resource building takes («Saca»); `G.baseToma`/`G.queSaca` read it.
- Old saves: a gatherer with no base gets one in `doGather` (and offline) via `G.baseParaRecurso`.
- **Slots are the new limit of the economy**: a pop of 150 needs ~15 camps. «Entrenar sin parar» stops with 4+ idle,
  the idle toast and the Asesor say «no free slots: build a camp», and the Asesor rule `radio` offers Mover for a
  camp whose radius ran dry. `A.lugarJunto` searches up to the camp radius (your land often ends before the ore).
- **Resource amounts:** `D.NODES[k].priv` multiplies amount and max of nodes **outside common zones** (trees and
  berries ×2.5, mines ×2) and divides their regen (same per hour). Common zones keep `amount`: the server still owns
  them until L4, so no function deploy was needed.
- The autopilot (`tools/piloto.js` → `campoExtra`) moves dry camps, places one where the plan's resource is out of
  reach and adds camps when idle villagers have no useful slot. Pace after L2: Era IV at 108 min (121 before), Era V
  not reached in 310 min (250 before) — iron is the bottleneck; measure again after L3/L4.
- Radius drawing: `circuloRadio` in `render.js` (ghost and selected building); panel `UI.basePanel`, Aldeanos window
  «Lugares de trabajo».

### L3, materials live in buildings, carromatos and the Gran Portón (`pk-43`)

- **Ledger (`js/mayor.js`, `PK.Libro`)**: town stores (anything with `G.capDe(b, r) > 0`: TC, Almacén, Granero) keep
  `b.inv`; **`S.res` is still the town total and still pays for everything**. `Lb.conciliar()` runs after every
  step, every offline chunk and before saving: what changed without a place (pay, reward, market…) is spread
  (spending from the fullest store; income to the nearest store with room, TC first; the excess over every cap stays
  in the TC — pk-34's "rewards go over the cap"). Old saves need no migration: the first run spreads `S.res`.
- **Anything with a place touches the building and `S.res` together** (`Lb.poner`/`Lb.sacar`): villager deposits,
  cart load/unload, bandit theft. Otherwise the conciliation "fixes" it by moving stock between stores.
- **Camps** (`Lb.esCampo`: lumber, mining, and a Mill **outside** your land — inside it is a town store, decision 4)
  keep `b.inv` that does **not** add to `S.res` (cap `D.campoCap(L)` = 300 + 150·(L−1), total). Their villagers wait
  when it is full (`G.llenoPara(base, res)`). Demolishing or moving one sends its stock to the town
  (`Lb.vaciarAlPueblo`). `Lb.fuera(r)` (camps + what vehicles carry) goes into the server snapshot so unloading a
  carromato is not a "jump" (`fotoRes` in `net.js`).
- **Carromato** (`kind: 'carromato'`, profile `carromato`): route from a camp to a town store or a workshop that uses
  its resource (`L.claseRuta(r)` = class by origin). Leaves your land, **never through a small gate (`W.wall` 2)**,
  only through the Gran Portón (3); foreign land without wall costs ×4 (`D.CARROMATO.ajeno`). `D.CARROMATO` speeds
  are tuned with the autopilot (faster off-road than planned: the plan's 0.55 left a forest camp at 30/min).
- `L.camino` tries up to 6 free tiles around the origin: a camp inside a forest used to start from a pocket enclosed
  by trees and report "no path".
- **Establo de Carromatos**: Era I, `max e => 1 + ⌊e/2⌋`, `2 + level` carromatos each; **the first one ever spawns a
  free carromato** (`st.flags.carroGratis`, also for old saves). Without it Era I jams.
- **Gran Portón**: two types, `granporton` (4×2) and `granportonv` (2×4, `alias`), rotated with R or «Girar»;
  `G.countAll/countB` count them together (`G.tipoDe`). Towers block; the 2×2 passage has `W.block` 0 and
  `W.wall` 3 (`G.marcarPorton`, re-applied by `Def.init`). It can be placed over your own walls/gates (they are
  removed with half back). Not movable. `findPath(noGate)` treats ≥ 2 as closed (wolves, bandits). `Def.remove`
  ignores 3. Sprite `Sp.porton(type, owner, wallTier, frame)` follows the wall material; `portonCuadro` in
  `render.js` opens it when a unit of yours is within 2.5 tiles and plays `porton` (`sfx/porton.mp3`, synthesized in
  code with `porton.py`-style math, gain measured like pk-38).
- Bandits now target camps too and steal up to 30% of **that** building's stock (era cap unchanged).
- Asesor rules `establo`, `porton`, `campoLleno`. Autopilot: `carromatos()` creates camp → nearest store routes,
  trains carromatos, upgrades/adds establos when it runs out.
- **Server**: `D.PROTO` was **not** bumped. An old server drops the two unknown building types from snapshots (and
  logs a `suspect`); deploying the function (`firebase deploy --only functions`) makes others see them.
