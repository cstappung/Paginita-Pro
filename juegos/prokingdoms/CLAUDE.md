# Pro Kingdoms (beta cerrada)

Isometric pixel-art kingdom builder, plain JS with no dependencies, all art
generated by code. Written by the owner outside this repo and dropped in as
is: `CONTEXTO.md` (how it is built, the platform bridge, the server protocol)
and `FIREBASE.md` (the cost study) are the author's notes. Read them before
touching the game itself. This file only covers how it lives inside Juegos.

## How it is wired

- **A `tipo: "sitio"` entry with `beta: true`** in `SOLOS`
  (`colabtex/src/juegos/salon-datos.js`), route `#prokingdoms`, full window
  like Mascotas (`html.jg-prokingdoms` in `juegos.html`). The postman is
  `colabtex/src/juegos/prokingdoms.js` (`crearProKingdoms`). The frame sends
  it `listo`, `volver` and `token` (the Firebase ID token for the server).
- **Only beta testers see it.** `betaTesters/<uid>` = `{at, por}`, written
  from the admin panel's «Beta testers» tab (`docs/claude/juegos/admin.md`).
  The rules let only admins write it. Each account reads **only its own entry**
  (`fb.watchBeta`), and admins read the whole list. The role is generic: any
  `SOLOS` entry with `beta: true` is filtered by `entradasSalon(..., {beta})`.
  Removing `beta: true` opens it to everyone. While the check is pending,
  `state.beta` is `null`: the salón hides the entry and the route shows
  «Comprobando…». It hides the game but does not lock it. The page is public
  like the rest of the site and writes nothing to the database, and the
  server checks `betaTesters` itself.
- **Guests never see it.** `libreParaInvitado` is false for every
  `beta` entry, and `MOTIVO_CUENTA.prokingdoms` is the login door.
- **The frame** loads `i18n.js`, `mando.js` and `volumen.js` first, then
  `sitio.js` (the bridge), then the game. `sitio.js` defines
  `window.ProKingdomsPlatform` before `js/social.js` reads it, and it prepends
  «← Juegos», the shared volume control and a BETA mark to the game's
  `#topbar`. It goes at the start because on a phone that bar scrolls
  sideways. The game's own mute (key M) stays.

## Beta decisions (change them only on purpose)

- **Local mode unless `servidor.json` has a `url`.** In that case the postman
  opens `index.html?local&perfil=<uid>&nombre=…`. Without `?local` the game
  would try `POST /api/join` on GitHub Pages: one 404 per load before falling
  back to local mode. With a URL, see the next section.
- **Local saves: one kingdom per account per browser.** The game suffixes its own keys
  with `?perfil` (`U.key`, max 20 chars of the uid). `sitio.js` suffixes the
  two keys the game leaves bare (`pk_site_coins`, the name). Nothing syncs
  across devices yet.
- **Its coins are the kingdom's, not Juegos'.** The browser adds them and
  nobody validates them, so they must not reach `monedas.js` until a server
  checks them. Wiring `addCoins` into the site economy would also need a new
  part in `ganadoDe`, the economy cierre and rules (see
  `perfiles-y-economia.md`).
- **Cache:** every script in `index.html` carries `?v=pk-N`, and the postman
  has `PK_VER`. Bump both whenever any game file changes. `stamp-version.js`
  only rewrites the `i18n.js` tag here.

## The online world: the Cloud Function (owner on Blaze, 2026-11-02)

The RTDB-only option (FIREBASE.md's option A) was rejected. RTDB download is
already the site's bottleneck (360 MB a day, the 90 MB per-player cap in
`consumo.js`, the economy cierre). It would also lose the server's anti-cheat.
The server is **`functions/`**, an HTTP Cloud Function `prokingdoms` in
us-central1. Deploy steps for the owner: `firebase/CONFIGURAR-FIREBASE.md`
§5. Not deployed by a push.

- **Same `server/sim.js`.** `functions/prepara.js` (the predeploy) copies
  `server/sim.js` and `js/{util,data,world}.js` into `functions/juego/`
  (git-ignored). It installs `functions/store-rtdb.js` there as `store.js`.
  `node server.js` and `tools/cheat-test.js` keep working locally. Run the
  cheat test after touching `sim.js`.
- **`sim.js` knobs:** `PK_TICK_PEREZOSO` removes the `setInterval`, and
  `functions/index.js` calls `sim.tick()` before a request when 5 s have
  passed (everything advances by elapsed time). `join({uid})` binds one
  kingdom per Firebase uid (`byUid`). Only the function sets `uid`, after
  `verifyIdToken`. `ONLINE_MS` is 40 s because sync is every 15 s.
  `PK_SAVE_MAX` is 2 MB.
- **One instance** (`maxInstances: 1`, `concurrency: 80`), because the world
  lives in memory. Cold start: `store.carga()` downloads `prokingdoms/col` and
  `prokingdoms/hayPartida` once. `flush()` uploads only changed docs, at most
  every 3 s and right after a join. Saves are awaited before the response, and
  SIGTERM flushes what is left.
- **Docs are stored as JSON strings** (`prokingdoms/col/<col>/<id>`), because
  the RTDB drops nulls in arrays and empty arrays/objects (`slots`, `inbox`).
- **Who gets in:** `POST /api/join` needs `Authorization: Bearer <Firebase ID
  token>` plus `betaTesters/<uid>` (`SOLO_BETA`). Every other route uses the
  game token that join returns (`X-PK-Token`, or `?t=` for `sendBeacon`, which
  sends `text/plain` to avoid a preflight). CORS only allows the site's
  origins, and a foreign `Origin` gets 403. The database URL is explicit in
  `initializeApp`: without it the emulator guessed another namespace.
- **Client:** the postman reads `servidor.json` (`url`; empty means local mode)
  and opens the frame with `?api=<url>` instead of `?local`. It answers the
  frame's `token` requests with `auth.currentUser.getIdToken()`. In `net.js`,
  `API` prefixes every call, sync is 15 s, cloud save is 120 s, and join waits
  15 s for a cold start. If join fails (server down, not a beta tester), the
  game falls back to local mode by itself.
- **Tests:** `cd functions && npm run prueba` runs against `firebase emulators:start
  --only auth,database,functions`. It is not idempotent: restart the emulators
  between runs. In a cloud session, start the emulators with the
  `HTTP(S)_PROXY` vars unset (firebase-tools 15 sent its own localhost calls
  through the proxy) and use `firebase-admin` modular imports (v14 dropped
  `admin.database()`).
- Kingdom coins are still local (`sitio.js`). Moving them to the site economy
  would be the server's job, not the browser's.

## Beta review, Nov 2026 (decisions; change them only on purpose)

- **Buildings build themselves.** `G.updateBuildings` advances `progress` of
  unfinished player buildings (`def.time / buildMult`). Villagers no longer build:
  the `build` task only survives in old saves and clears itself. Placing comes
  from the **Construir** menu (`UI.openBuild`, key C), not from the villager
  panel. On touch, the first tap shows the ghost and a second tap on it (or
  «Construir aquí») builds it (`PK.Input.placeGhost`).
- **Villagers get jobs.** `PK.Auto.JOBS`, `setJob`, `addJob` and `removeJob`
  (the «Aldeanos» window, which also holds the Capataz). A player order sets
  `task.m`, and the Capataz never undoes it (stalled workshops only release
  the workers it placed). `u.hold` is «idle on purpose». `G.bestNode` picks
  nodes by distance to the villager and to its drop point plus a crowding
  penalty (`G.nodeRoom`), and widens the search before giving up. Two walking
  villagers don't push each other (`separate`).
- **Troops are drawn, not simulated** (`js/troops.js`). The garrison stands in
  front of the barracks, and columns march along an A* route by the time
  fraction of each run. The fight plays at arrival. Nothing of it is saved or
  sent to the server. Bandit camps go through the expedition planner
  (`PK.Exp` target `{ camp }`). `war.exps` camp entries are legacy. Each battle
  leaves a report in `war.reports` (`UI.openReport`).
- **Digits use Jersey 10** (`css/numeros.woff2`, OFL, 0-9 only via
  `unicode-range`, `size-adjust: 125%`), because in Pixelify Sans the 2, 5 and
  8 look alike. The canvas uses the same stack (`"PK Num", "Pixelify Sans"`).
- **Balance:** only rates, regrow times and costs changed in `data.js`. Node
  `amount`s are untouched because the server uses them for the shared zones.
- **Redraws keep scroll.** `UI.rerender` and `refreshPanel` rebuild everything,
  so they snapshot and restore every element's scroll, and they skip the timed
  redraw while the user is touching or scrolling (`watchTouch`). Pass
  `rerender(true)` when switching tabs. On phones, modals are full screen.
- **Map events** have a banner that shrinks to a pill (✕, after 15 s, or always
  with Opciones → «Eventos achicados», `flags.evMin`). Toasts close on tap.
  Chests open with `UI.chestReveal`.
- **Trapped villagers get rescued** (`unstick` in `entities.js`, every second).
  On a tile that became blocked (a wall drawn over them, a tree regrown or
  revived by the server, an event node), they step to the nearest free tile.
  Standing still for 6 s (2 s after failed paths) outside the region of their
  Centro Urbano (`W.regionAt`) means enclosed, so they jump back to it. Never
  rescue by distance or by path failures alone: a villager in its home region
  is never trapped, only waiting.

## Playtest fixes, Nov 2026

- **Gold has no `MARKET_BASE` entry** (that table also feeds the guild's
  needs). `social.js` prices it at 100 through `price()`. Without it, gold
  offers came out as «200 oro por 0» and accepting one set a resource to NaN.
  Saved offers that are not valid are dropped at load.
- **`U.dayKey` does not zero-pad** («2026-11-2»). Parse it with `parseDay`,
  never `new Date(key + 'T00:00:00')`, which gave «faltan NaNs».
- **`Element.append(null)` writes «null».** Pass `''` for an optional child
  (`U.el` skips nulls, but bare `append` does not).
- **The panel hides when empty** (`#hud.p-none`): with «Ocultar ayuda»
  (`flags.helpOff`) and nothing selected, the map is free.
- **Portrait phones under 600 px wrap the top bar into two rows.** In one
  scrolling row, population, era and coins sat off screen.
- **Why villagers are idle:** `PK.Auto.whyText` (never seen, depleted with
  regrow ETA, or out of reach), and `idleHint` warns at most every 3 min.
- **Tactics** (`PK.Exp.TACTICS`: asalto, normal, cauto) change power and
  losses until arrival. A toast 20 s before arrival offers «Ver combate».
- **One toast per batch** for finished quests, «Reclamar todo»
  (`Quests.claimAll`) with one chest, («lleno»: see below).
  Auto-train leaves one slot for the scout. Tc level 1 stores 800.
- The 🌐 language picker only floats when the page is opened alone
  (`i18n.js` skips it inside a frame), so in Juegos it never covers the game.
- **Toasts are prepended (newest first).** Hide extras with
  `:nth-child(n+K)`, never `:nth-last-child`, which hid the newest. At most 3
  on desktop and 2 on phones. «Lleno» is one toast every 2 min listing every
  full resource. «Explorador sin alcance» shows once per range
  (`flags.scoutDoneR`).
- **The upgrade queue skips what it cannot pay yet** and keeps the order for
  the rest. «Ocupar los talleres» also moves one Capataz gatherer (never a
  `task.m` one) to a free workshop slot every 10 s.
- **Approximate numbers say «aprox.»**: in Pixelify Sans «~79» reads as «-79».
