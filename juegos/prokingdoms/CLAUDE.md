# Pro Kingdoms (beta cerrada)

Isometric pixel-art kingdom builder, plain JS with no dependencies, all art
generated by code. Written by the owner outside this repo and dropped in as
is: `CONTEXTO.md` (how it is built, the platform bridge, the server protocol)
and `FIREBASE.md` (the cost study) are the author's notes. Read them before
touching the game itself. This file only covers how it lives inside Juegos.

## How it is wired

- **A `tipo: "sitio"` entry with `beta: true`** in `SOLOS`
  (`colabtex/src/juegos/salon-datos.js`), route `#prokingdoms`, full window
  like Mascotas (`html.jg-prokingdoms` in `juegos.html`). The postman is
  `colabtex/src/juegos/prokingdoms.js` (`crearProKingdoms`). The frame sends
  it `listo`, `volver` and `token` (the Firebase ID token for the server).
- **Only beta testers see it.** `betaTesters/<uid>` = `{at, por}`, written
  from the admin panel's «Beta testers» tab (`docs/claude/juegos/admin.md`).
  The rules let only admins write it. Each account reads **only its own entry**
  (`fb.watchBeta`), and admins read the whole list. The role is generic: any
  `SOLOS` entry with `beta: true` is filtered by `entradasSalon(..., {beta})`.
  Removing `beta: true` opens it to everyone. While the check is pending,
  `state.beta` is `null`: the salón hides the entry and the route shows
  «Comprobando…». It hides the game but does not lock it. The page is public
  like the rest of the site and writes nothing to the database, and the
  server checks `betaTesters` itself.
- **Guests never see it.** `libreParaInvitado` is false for every
  `beta` entry, and `MOTIVO_CUENTA.prokingdoms` is the login door.
- **The frame** loads `i18n.js`, `mando.js` and `volumen.js` first, then
  `sitio.js` (the bridge), then the game. `sitio.js` defines
  `window.ProKingdomsPlatform` before `js/social.js` reads it, and it prepends
  «← Juegos», the shared volume control and a BETA mark to the game's
  `#topbar`. It goes at the start because on a phone that bar scrolls
  sideways. The game's own mute (key M) stays.

## Beta decisions (change them only on purpose)

- **Local mode unless `servidor.json` has a `url`.** In that case the postman
  opens `index.html?local&perfil=<uid>&nombre=…`. Without `?local` the game
  would try `POST /api/join` on GitHub Pages: one 404 per load before falling
  back to local mode. With a URL, see the next section.
- **Local saves: one kingdom per account per browser.** The game suffixes its own keys
  with `?perfil` (`U.key`, max 20 chars of the uid). `sitio.js` suffixes the
  two keys the game leaves bare (`pk_site_coins`, the name). Nothing syncs
  across devices yet.
- **Its coins are the kingdom's, not Juegos'.** The browser adds them and
  nobody validates them, so they must not reach `monedas.js` until a server
  checks them. Wiring `addCoins` into the site economy would also need a new
  part in `ganadoDe`, the economy cierre and rules (see
  `perfiles-y-economia.md`).
- **Cache:** every script in `index.html` carries `?v=pk-N`, and the postman
  has `PK_VER`. Bump both whenever any game file changes. `stamp-version.js`
  only rewrites the `i18n.js` tag here.

## The online world: the Cloud Function (owner on Blaze, 2026-11-02)

The RTDB-only option (FIREBASE.md's option A) was rejected. RTDB download is
already the site's bottleneck (360 MB a day, the 90 MB per-player cap in
`consumo.js`, the economy cierre). It would also lose the server's anti-cheat.
The server is **`functions/`**, an HTTP Cloud Function `prokingdoms` in
us-central1. Deploy steps for the owner: `firebase/CONFIGURAR-FIREBASE.md`
§5. Not deployed by a push.

- **Same `server/sim.js`.** `functions/prepara.js` (the predeploy) copies
  `server/sim.js` and `js/{util,data,world}.js` into `functions/juego/`
  (git-ignored). It installs `functions/store-rtdb.js` there as `store.js`.
  `node server.js` and `tools/cheat-test.js` keep working locally. Run the
  cheat test after touching `sim.js`.
- **`sim.js` knobs:** `PK_TICK_PEREZOSO` removes the `setInterval`, and
  `functions/index.js` calls `sim.tick()` before a request when 5 s have
  passed (everything advances by elapsed time). `join({uid})` binds one
  kingdom per Firebase uid (`byUid`). Only the function sets `uid`, after
  `verifyIdToken`. `ONLINE_MS` is 40 s because sync is every 15 s.
  `PK_SAVE_MAX` is 2 MB.
- **One instance** (`maxInstances: 1`, `concurrency: 80`), because the world
  lives in memory. Cold start: `store.carga()` downloads `prokingdoms/col` and
  `prokingdoms/hayPartida` once. `flush()` uploads only changed docs, at most
  every 3 s and right after a join. Saves are awaited before the response, and
  SIGTERM flushes what is left.
- **Docs are stored as JSON strings** (`prokingdoms/col/<col>/<id>`), because
  the RTDB drops nulls in arrays and empty arrays/objects (`slots`, `inbox`).
- **Who gets in:** `POST /api/join` needs `Authorization: Bearer <Firebase ID
  token>` plus `betaTesters/<uid>` (`SOLO_BETA`). Every other route uses the
  game token that join returns (`X-PK-Token`, or `?t=` for `sendBeacon`, which
  sends `text/plain` to avoid a preflight). CORS only allows the site's
  origins, and a foreign `Origin` gets 403. The database URL is explicit in
  `initializeApp`: without it the emulator guessed another namespace.
- **Client:** the postman reads `servidor.json` (`url`; empty means local mode)
  and opens the frame with `?api=<url>` instead of `?local`. It answers the
  frame's `token` requests with `auth.currentUser.getIdToken()`. In `net.js`,
  `API` prefixes every call, sync is 15 s, cloud save is 120 s, and join waits
  15 s for a cold start. If join fails (server down, not a beta tester), the
  game falls back to local mode by itself.
- **Tests:** `cd functions && npm run prueba` runs against `firebase emulators:start
  --only auth,database,functions`. It is not idempotent: restart the emulators
  between runs. In a cloud session, start the emulators with the
  `HTTP(S)_PROXY` vars unset (firebase-tools 15 sent its own localhost calls
  through the proxy) and use `firebase-admin` modular imports (v14 dropped
  `admin.database()`).
- Kingdom coins are still local (`sitio.js`). Moving them to the site economy
  would be the server's job, not the browser's.

## Beta review, Nov 2026 (decisions; change them only on purpose)

- **Buildings build themselves.** `G.updateBuildings` advances `progress` of
  unfinished player buildings (`def.time / buildMult`). Villagers no longer build:
  the `build` task only survives in old saves and clears itself. Placing comes
  from the **Construir** menu (`UI.openBuild`, key C), not from the villager
  panel. On touch, the first tap shows the ghost and a second tap on it (or
  «Construir aquí») builds it (`PK.Input.placeGhost`).
- **Villagers get jobs.** `PK.Auto.JOBS`, `setJob`, `addJob` and `removeJob`
  (the «Aldeanos» window, which also holds the Capataz). A player order sets
  `task.m`, and the Capataz never undoes it (stalled workshops only release
  the workers it placed). `u.hold` is «idle on purpose». `G.bestNode` picks
  nodes by distance to the villager and to its drop point plus a crowding
  penalty (`G.nodeRoom`), and widens the search before giving up. Two walking
  villagers don't push each other (`separate`).
- **Troops are drawn, not simulated** (`js/troops.js`). The garrison stands in
  front of the barracks, and columns march along an A* route by the time
  fraction of each run. The fight plays at arrival. Nothing of it is saved or
  sent to the server. Bandit camps go through the expedition planner
  (`PK.Exp` target `{ camp }`). `war.exps` camp entries are legacy. Each battle
  leaves a report in `war.reports` (`UI.openReport`).
- **Digits use Jersey 10** (`css/numeros.woff2`, OFL, 0-9 only via
  `unicode-range`, `size-adjust: 125%`), because in Pixelify Sans the 2, 5 and
  8 look alike. The canvas uses the same stack (`"PK Num", "Pixelify Sans"`).
- **Balance:** only rates, regrow times and costs changed in `data.js`. Node
  `amount`s are untouched because the server uses them for the shared zones.
- **Redraws keep scroll.** `UI.rerender` and `refreshPanel` rebuild everything,
  so they snapshot and restore every element's scroll, and they skip the timed
  redraw while the user is touching or scrolling (`watchTouch`). Pass
  `rerender(true)` when switching tabs. On phones, modals are full screen.
- **Map events** have a banner that shrinks to a pill (✕, after 15 s, or always
  with Opciones → «Eventos achicados», `flags.evMin`). Toasts close on tap.
  Chests open with `UI.chestReveal`.
- **Trapped villagers get rescued** (`unstick` in `entities.js`, every second).
  On a tile that became blocked (a wall drawn over them, a tree regrown or
  revived by the server, an event node), they step to the nearest free tile.
  Standing still for 6 s (2 s after failed paths) outside the region of their
  Centro Urbano (`W.regionAt`) means enclosed, so they jump back to it. Never
  rescue by distance or by path failures alone: a villager in its home region
  is never trapped, only waiting.

## Playtest fixes, Nov 2026

- **Gold has no `MARKET_BASE` entry** (that table also feeds the guild's
  needs). `social.js` prices it at 100 through `price()`. Without it, gold
  offers came out as «200 oro por 0» and accepting one set a resource to NaN.
  Saved offers that are not valid are dropped at load.
- **`U.dayKey` does not zero-pad** («2026-11-2»). Parse it with `parseDay`,
  never `new Date(key + 'T00:00:00')`, which gave «faltan NaNs».
- **`Element.append(null)` writes «null».** Pass `''` for an optional child
  (`U.el` skips nulls, but bare `append` does not).
- **The panel hides when empty** (`#hud.p-none`): with «Ocultar ayuda»
  (`flags.helpOff`) and nothing selected, the map is free.
- **Portrait phones under 600 px wrap the top bar into two rows.** In one
  scrolling row, population, era and coins sat off screen.
- **Why villagers are idle:** `PK.Auto.whyText` (never seen, depleted with
  regrow ETA, or out of reach), and `idleHint` warns at most every 3 min.
- **Tactics** (`PK.Exp.TACTICS`: asalto, normal, cauto) change power and
  losses until arrival. A toast 20 s before arrival offers «Ver combate».
- **One toast per batch** for finished quests, «Reclamar todo»
  (`Quests.claimAll`) with one chest, («lleno»: see below).
  Auto-train leaves one slot for the scout. Tc level 1 stores 800.
- The 🌐 language picker only floats when the page is opened alone
  (`i18n.js` skips it inside a frame), so in Juegos it never covers the game.
- **Toasts are prepended (newest first).** Hide extras with
  `:nth-child(n+K)`, never `:nth-last-child`, which hid the newest. At most 3
  on desktop and 2 on phones. «Lleno» is one toast every 2 min listing every
  full resource. «Explorador sin alcance» shows once per range
  (`flags.scoutDoneR`).
- **The upgrade queue skips what it cannot pay yet** and keeps the order for
  the rest. «Ocupar los talleres» also moves one Capataz gatherer (never a
  `task.m` one) to a free workshop slot every 10 s.
- **Approximate numbers say «aprox.»**: in Pixelify Sans «~79» reads as «-79».

## Fun pass, Nov 2026 (playtests at 6/10)

- **Bandit raids** (`js/incursiones.js`, `PK.Incursiones`) from Era II, live play
  only like the wolves: never offline, in `?timelapse` or on the server. Only
  the clock to the next one is saved (`state.inc`, defaults for old saves).
  Camp + horn + `aviso` countdown, then a march on the nearest storage. TC and
  towers shoot them through `Life.arrows` (`a.fn` callback); home troops sally
  (drawn figures, damage from `Social.power`, garrison hidden meanwhile).
  Looting takes up to 12% of food/wood/stone/gold, capped per era, and killing
  a carrier returns its share. A win counts `raids_won` and `defenses_won`
  (quests w5, w11, w12). Walls that cut the path turn it into a siege.
- **Horas extra** (`G.otInfo`/`G.overtime`): pay 12% of each storage cap in
  food, wood and stone to skip 10% of an era advance (max 8) or 12.5% of an
  upgrade of 2 min or more (max 4), +30% per payment on the same timer
  (`t.ot`). It is the surplus sink. Keep it priced off caps, not a table.
- **Progressive menu** (`MENU_VER` in `ui.js`): Explorar, Investigar, Mercado,
  Gremio, Territorio, Logística and Reinos show up when they make sense and
  stay (`flags.menu_<id>`). Cuartel is always there (walls from Era I). What
  appears mid-session glows (`.nuevo`); on load nothing is announced.
  Territorio also appears after a «tierra libre» placement (`flags.verTerr`).
- **The minimap frames the explored area** (`R.mmView`, eased) instead of the
  whole world. `minimapToTile` and the camera box go through that view.
- **Phones start at zoom 1** (smaller side under 560 px).

## Live battles and touch deselect, Nov 2026

- **Camp and dungeon runs are fought live** (`js/batalla.js`, `PK.Batalla`)
  when they arrive while you play: `r.phase = 'battle'`, simulated in
  `G.update` whether or not anyone watches, and drawn on its own full-screen
  map («Ver batalla», `#batalla`). Its result and losses go through
  `Exp.finishBattle(r, res)` → `resolve(r, res)`. Missions, the offline
  calculation (`B.adelantar`, played to the end at once) and a reload mid-fight
  (no battle in memory → old formula) keep working without it. Nothing of it is
  saved or sent to the server.
- **Balance rule:** each figure's hp and damage come from `Exp.powerVs`, and our
  hp also gets `vsFactor`, so the planner's «fuerza contra» is what fights
  (strength ∝ power² on both sides). Measured with `B.adelantar` over many
  fights: bandits ~50% at 1:1 and ~100% at 1.3:1; the dragon needs «dispersar».
- **Orders matter on purpose:** `linea` (spears ×1.35 against fast enemies and
  the dragon), `dispersar` (fire and catapult splash hit fewer), focus on an
  enemy type, retreat (fewer losses). Below 20% life the army retreats by
  itself. `B.CONSEJO` tells the player which order fits each enemy.
- **Touch deselect:** tapping empty ground releases the selection (it used to
  send villagers walking there), as does tapping the only selected villager
  again or the panel's ✕. The TC rally point is set by tapping a resource.
- **Battle scenery** lives in `js/escenarios.js` (`PK.Escenarios`): one
  procedural pixel-art scene per place (camp at dusk, crystal cave, lair,
  crypt, crater, dragon nest). It covers the whole screen (`escenario()` in
  `batalla.js` stretches the field plus a margin to the screen shape), with a
  static background, a front layer (stalactites, roots), animated decor and a
  darkness-with-lights pass. While the battle is open the kingdom map is not
  drawn (`main.js`), which kept it near 60 fps.

## Playtest 3 fixes and battle effects, Nov 2026 (playtest at 7/10)

- **One storage-cap rule:** the cap only limits what villagers gather and workshops
  make. Rewards, chests, loot, market buys, sells and trades always enter whole,
  even over the cap. Never route a deliberate transaction through `G.addRes`
  (selling with gold full used to eat the goods).
- **Full storage makes gatherers wait** (`G.isFull`, `u.fullWait`, «Esperando:
  bodega llena») instead of stripping the node and throwing the load away. The
  offline calculation does the same, and its «agotaron» count only counts your
  villagers' nodes (it counted the 15 simulated kingdoms too).
- **A workshop with no supply** (`PK.Logi.supplied`: not near storage, no carts,
  no belt) takes no workers: `G.command` refuses with a toast, and the Capataz,
  «Talleres» and `jobAvailable` skip it.
- **Fiesta del pueblo** (`G.fiesta`, TC panel, Era II+): 15% of the food, wood,
  stone and gold caps (+40% per fiesta the same day) for +25% gathering and
  workshops for 5 min, via `Date.now()` like the wishing well. It is the surplus
  sink when there is no timer for horas extra. The server's `LIM.slack` (2.5x)
  covers it.
- **The era is a button:** the bar shows «meta 2/3» or «¡avanzar!», and a tap
  opens `UI.openEraGoal` (requirements plus cost with have/need).
- **Toasts group:** a toast whose text matches a visible one, ignoring the
  numbers, updates it with «×N» instead of stacking. «Lleno» drops to every
  6 min after 3 warnings.
- Phones: the portrait panel's height is `--ph` (40vh; the menu, toasts and
  event box sit on it). In landscape the side menu has two 40 px columns
  (`--mw: 96px`) and a «▼ más» cue. On phones, Obras rows take one line and the
  whole row opens the building.
- **Battle effects** (`batalla.js`, «Efectos»): sparks, claw slashes, knockback,
  lunges, white hit flash, dust, camera shake, arcing rocks with ground shadows,
  aimed arrows, glowing bolts, dragon fire from the mouth, ground marks,
  fall-over deaths, order shouts, the opening banner, fireworks and victory
  rays. Combat lights go to the scene's darkness pass through `esc.extra`
  (`Escenarios.luz`). All of it lives in `vista`, so with nobody watching it is
  not created and the fight is unchanged. Never put a balance number in there.

## Deeper floors look deeper; moving buildings, Nov 2026

- **Scenery depth** (`escenarios.js`): every place gets ground relief (`relieve`,
  a height map lit from the top left), rock ledges off the walls (`meseta`),
  distance haze at the top (`profundidad`, `esc.bruma`), and dark foreground
  silhouettes in the front layer (`primerPlano`).
- **Each floor is more spectacular than the last.** `batalla.js` passes `nivel`
  (0 first floor … 1 last floor; for camps, `poiTier / 6`) to
  `Escenarios.crear`. Colors drift toward the place's own tone (`HONDO`), it
  gets darker with more lights and decor, and features unlock by depth:
  - Cave: pulsing crystal veins, a giant geode, floating shards, light shafts.
  - Lair: ribcages, a giant skull with glowing eyes, eyes in the dark.
  - Crypt: green braziers, a rune circle, statues, a portal.
  - Crater: lava pools, the fallen star, shooting stars.
  - Nest: lava, ruined pillars, the bones of a dead dragon.
  - Camp: watchtowers, braziers, stone walls instead of logs, more tents.
  - The last floor's banner says «¡Último piso!».
- **Performance:** the darkness mask is drawn at half resolution, the battle
  vignette is baked into the front layer, and deep caves light every second
  crystal. Set one `fillStyle` per crack or vein, never one per point.
- **Moving buildings** (`G.moveBuilding`, `PK.Input.startMoving`, panel
  «Mover» or key V): the same ghost as building, with `placeWhy(type, x, y,
  ignorar)` treating the building's own tiles as free. It keeps level, upgrade
  timer, construction, queue, workers and buffers. It costs 10% of the base
  cost and drops the belts that reached it. The TC cannot move
  (`G.MOVE_NO`): home regions and rescues hang on it.

## The mega update plan, Phase 0 (`pk-11`, Nov 2026)

`PLAN-MEGA-ACTUALIZACION.md` (this folder) is the owner's plan, phase by phase
(«implementa la Fase N del plan»). Its rules section applies to every phase.

- **`scared` goes negative after a fright.** Test `u.scared > 0`, never
  `!u.scared`: a leftover −0.03 locked 132 of 159 villagers out of «+» (B1).
- **No building may close the TC's yard** (`G.encierra`, reason `'encierra'` in
  `placeWhy`, also for moves). It compares how many tiles you can walk to from
  the TC's sides before and after (`W.reachCount`, 4-way like the regions and
  A*, which never cuts corners). A town that was already closed (walls without a
  gate) is not blocked. If a yard still ends up closed, `G.checkEncierro` (every
  5 s) sets `G.encierro`: red arrows on the buildings that open it, new
  villagers spawn outside, `unstick` rescues outward, the idle hint stops
  saying «explora» (B2).
- **Common-zone stats also count by type** (`z_tree`). Quest `e3` asked for
  `z_forest`, which nobody wrote (B3).
- **Workshops held by the reserve say so** (`G.reservaDe`, status «En
  reserva»), and `b.sinReserva` («Producir igual», saved) skips it for one
  workshop. New games start at 15% (B4).
- **Changing a Capataz priority rebalances** up to 10 of its villagers
  (`PK.Auto.rebalance`), never a `task.m` order (B5). The hover tip refreshes
  every 250 ms and on camera moves (B7).
- **World resets** (P1): bump `D.MUNDO_VER` (and `D.SAVE_V`) and deploy the
  function. `sim.js` compares it on load with the stored one (`mundo.json`
  locally, `prokingdoms/mundoVer` in the RTDB) and calls `store.reinicia()`,
  which wipes everything but the suspicion log. No stored version just writes
  it. A save of another `SAVE_V` shows the «Un mundo nuevo» card once
  (`D.NOVEDADES`: update it in every delivery that resets).
- **`D.PROTO`** goes in `POST /api/join`. Another one gets 426, and the loading
  screen offers «Jugar sin conexión». Bump it whenever both sides must agree
  (map, routes, limits), since Pages publishes on merge and the function is
  deployed by hand.
- **Tests:** `colabtex/tests/prokingdoms.test.cjs` (in `test:juegos`) checks
  the data tables, B1, B2 and the reset. Its POI fingerprint
  (`tests/fixtures/prokingdoms-pois.json`) must change only with a deliberate
  reset (new `D.MAPV`). Regenerate it with the snippet at the top of that
  file. The «two good troops per enemy» check is a `todo` until Phase 4: beasts
  only have the Lancero.

## Phase 1, automation (`pk-12`)

- **Capataz:** «Reequilibrar» (`auto.rebal`, on) moves up to 3 of its villagers
  every 20 s, only past 8% of the population. Plans (`PK.Auto.PLANES`,
  `auto.plan`); «Meta de era» turns what the next era and the upgrade queue
  lack into raw resources (`A.crudo`) every minute. Touching + or − returns to
  «A mano». `A.tick` timers count seconds (`el`), not calls: offline calls
  bring 60 s each.
- **Salón del Consejo** (`consejo`, Era II, one; `js/consejo.js`): one
  counselor per level 1/2/3/5/7/9, each with its own on/off and cadence, run
  from `A.tick` (offline too) inside `UI.mute`, so they never toast. What they
  do goes to `consejo.log` and the «Mientras no estabas» report
  (`Consejo.informe`). The Tesorero stays under the server's daily market
  cap (`C.MERCADO_DIA` < `LIM.marketDay`, tested). The Mayordomo also starts
  the era advance when it can (acceptance: 12 h away still advances).
- **Exploration flags** (`S.banderas`, max 3, `G.ponerBandera`,
  `PK.Input.startFlag`, map or minimap): the first scout (two with the Puesto
  at level 5 or Cartografía III) heads to the frontier tile nearest its flag.
  A flag goes away once its tile is revealed. Out of range is refused.
- **Outposts:** every 30 s live, a weighted resource with no node within 20
  tiles of its drop points offers a camp next to the nearest one
  (`A.lejos`, `A.lugarJunto`, `A.proponerCampo` leaves the ghost armed).
  Walking share per resource (`A.eficiencia`) shows in Aldeanos.
- **Asesor** (`js/asesor.js`, «?» in the top bar): ordered rules returning
  `{prioridad, texto, acciones}`. The top one also shows in the report.
  Phase 6 (U2) reuses it.
- **Barrio:** Shift (or «Modo barrio» for touch) snaps the next houses to the
  first one's grid with 1-tile streets and paves the street below and right
  when there is stone (`calles` in `input.js`).

## Split UI and the test autopilot (`pk-13`)

- **`js/ui.js` is split** (T5): the core stays there; the Cuartel and battle
  reports go to `js/ui/cuartel.js`, the kingdom windows (Obras, Territorio,
  Logística, Reinos…) to `js/ui/reino.js`, Aldeanos and the Capataz to
  `js/ui/aldeanos.js`, the Libro de Misiones to `js/ui/libro.js`. Each one
  adds functions to `PK.UI` and loads right after `ui.js` in `index.html`.
  The core calls `UI.barracksQuick`, `UI.enemyText` and `UI.bestVs`, so
  those must stay on `UI`. A new window gets its own file there.
- **The autopilot** (`tools/piloto.js`, T1) loads only with `?dev&piloto[=N]`
  (speed ×N, default 10) or `?timelapse` (×40, no save; T2, replaces the lost
  `tools/timelapse.js`). It builds a plan per era, keeps the builders busy,
  researches the cheapest tech, uses the Mariscal's logic at 80%, and claims
  quests, all under `UI.mute`. `pkPiloto.resumen()` gives minutes per era,
  villagers idle over 60 s, full-storage events and battles. Run it before
  and after any balance change and compare. Never let the game depend on it.
- **The autopilot places workshops next to storage** (`lugarTaller`, within
  `D.NEAR_STORE` of the TC or a warehouse). Elsewhere they get no supply and
  no workers, and it stalled in Era II for lack of planks. «ociosos» is the
  average share of idle villagers, not a count: at ×40 one villager crossed
  «60 s idle» many times a minute.

## Heroes (`pk-14`, H1 and C2)

## Mazmorras 2.0 (`pk-15`, H3 and C3)

- **Every dungeon visit is an incursion** of a 5-floor block (1–5, 6–10,
  11–15; `js/incursion.js`, `PK.Inc`). It rides on the expedition: `r.inc`
  holds the floor, the room options, the loot so far, blessings and losses.
  A room with a fight sets `r.need` and goes back to phase `'go'` with
  arrival in 2.5 s, so the live battle, the ratio formula and offline all
  stay the same code. New phases: `'sala'` (waiting for a choice) and
  `'fin'` (ended between rooms, i.e. retreat). `troops.js`, the timer strip
  and the Cuartel treat both as «at the dungeon».

  `I.porDefecto`: heal if needed, then the safe ones, never the merchant.
- **Loot:** each room gives `I.BOTIN_SALA` (35%) of a floor's loot, because a
  trip now brings five floors before the dungeon rests. Without it the cave
  gave 337 crystals per trip instead of about 90. Coins only on a first
  clear, never multiplied. A lost incursion keeps half (`arrive` gives it).
- **Bosses** (`JEFE` in `batalla.js`, Annex A2) on the last floor of every
  block take 55% of the room's power. Measured with 60 fights per boss at
  1.2× power and no veterancy (it skews the numbers: `jefes.js` in the
  session): right orders ≈ the same fight without a boss, wrong ones far
  lower (cave 22/0, lair 55/32, crypt 77/0, crater 68/2, nest 92/40). Keep a
  boss's `hp × dps` close to a normal enemy of its kind: the Matriarca at
  2.2 × 1.1 was unbeatable.

  (ranged −8): with −8 the spears held the line staring at a far boss while
  wolves bit them.
